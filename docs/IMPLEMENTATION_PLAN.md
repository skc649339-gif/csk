# iPhone 自用版实施计划

日期：2026-11-03。基线 `a600484a49255039d0725f1ba9e11ca81a948f97`；独立分支 `feature/iphone-pwa`。原功能与缺陷见 [UPSTREAM_AUDIT.md](./UPSTREAM_AUDIT.md)。本文件记录实施顺序与验收口径，具体完成状态以根目录最终报告为准。

## 目标与技术选择

保留 Next.js、React、TypeScript 和现有 `lib/ziwei` 排盘引擎，改为静态导出并增加PWA。核心排盘、解释和命盘存储都在手机浏览器中执行。生产部署上传静态产物即可，无需常驻Windows电脑、Mac、Xcode、Apple开发者账号或付费API。

第一阶段不增加登录、会员、支付、广告、跨设备同步；已保存资料只保存在当前浏览器/主屏幕App对应的本地站点存储。不会把开源仓库没有的商业站解读能力列为已保留功能。

## 测试要求与判定

1. **TypeScript**：运行类型检查命令，记录通过/失败和工具版本。
2. **单元测试**：保留原上游测试，补充历法接入、命盘存储、PWA必要逻辑测试；生产代码变更后重跑受影响检查。
3. **生产构建**：实际运行静态生产构建；确认核心页面、脚本、图标、manifest与SW都进入产物。
4. **Manifest**：检查 name/short_name/start_url/scope/display/icons 与实际文件，确认使用 standalone 和同源路径。
5. **Service Worker**：实际安装并读取CacheStorage；缓存就绪后断网打开核心页面、访问/重开命盘。脚本级模拟测试与真实浏览器测试分别标明。
6. **持久化**：保存至少两张不同记录，刷新/关闭页面再打开，核对记录与命盘；删除一张不影响另一张；存储写入失败不可显示假成功。
7. **排盘回归**：运行上游真实日期、性别、时辰索引、晚子时/经度换日、农历闰月、四化、格局等测试；新增输入不改变已有默认排盘口径。
8. **Safari兼容**：静态检查iOS元数据、触控、安全区与受支持API；有WebKit工具时运行引擎级浏览器测试；两者均不可冒充真实iPhone。

## 真实 iPhone 必验场景

- Safari访问最终HTTPS地址并完成首次缓存。
- 分享菜单→添加到主屏幕，图标名称为「紫微斗数」。
- 主屏幕启动为独立窗口，安全区/软键盘不遮挡核心操作。
- 公历与农历各排一张盘，查看宫位/星曜详情与大限/流年。
- 保存两张盘，完全关闭再打开仍存在，删除一张后另一张仍存在。
- 首次安装缓存完成后开飞行模式，从图标冷启动，查看已保存盘并测试本地排盘。
- 电脑关机后联网访问不受影响；部署更新后检查旧记录仍存在。

没有真实iPhone或最终部署授权时，明确标注「待实机验收」/「待HTTPS部署」，不宣称第一阶段最终成功标准已达成。

## 交付边界

本地存储受iOS站点数据管理影响；清除网站数据、移除App、隐私浏览和系统回收可能影响数据。可在交付中提供用户主动导出/导入备份，不以服务端同步代替本地优先。离线能力需先完成联网加载和缓存；未缓存的外部视频/链接不承诺离线。真实托管与实机验收属于最终闭环，不能用本地localhost成功代替。
