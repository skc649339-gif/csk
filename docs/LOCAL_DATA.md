# 本地命盘与旧历史记录

新版使用当前网站来源下的 `localStorage`，键名是 `ziwei-personal-records-v1`。每条记录包含随机编号、出生信息、完整命盘快照、创建时间和更新时间，数据封装版本为 `1`。不上传出生信息，不去重，也不再沿用旧版只保留十条的上限；最终容量由 Safari 的网站数据配额决定。

保存与删除只有在写入并回读成功后才会完成。空间不足、存储权限被限制、JSON 损坏、版本不兼容或命盘结构校验失败都会显示错误，不会把损坏的已有内容静默当成空列表覆盖。命盘快照保持上游引擎原输出，包括 iztro 用空字符串表示的“无四化”标记。

使用页面的“导出备份”把命盘 JSON 保存到“文件”App。导入是追加操作，每条导入记录获得新编号；同一备份导入两次会有两份记录，方便保留原记录，不会覆盖原盘。单个导入文件限制为 20 MB。浏览器网站数据被清理、卸载后重装、域名改变或 Safari 与主屏幕应用的数据隔离，都可能需要重新导入备份。

## 上游 `ziwei_history` 的迁移边界

上游 `lib/ziwei/history.ts` 曾把最多十条出生表单写入 `ziwei_history`；这些条目只有 `form`，没有完整命盘快照、流派设置或数据版本。新版**不会删除、覆盖或自动转换这个旧键**，也不会把它误认成新版备份。

当前版本没有自动迁移旧历史的界面。已有旧条目的用户应先保留旧网页/原网站数据，在原表单历史中逐条核对出生日期、钟表时间、出生地和性别，再在新版重新输入、核对并保存，最后导出新版备份。这个过程会使用当前已验证引擎重新排盘，不保证保留未知旧流派或旧引擎输出。批量迁移只有在补齐旧结构校验、迁移前备份、逐条预览和用户确认后才应实现；不能直接改键名或自动按默认流派覆盖旧结果。

## 第一版时间输入边界

支持公历、农历和闰月，日期通过上游 `lunar-solar.ts` 严格校验；不存在的闰月和小月三十日会阻止起盘。公农历转换后统一进入原 `formToBirthInfo`，沿用其经度校正和晚子时换日规则。

界面出生地列表为国内城市，时间按北京时间 UTC+8 标准时输入。夏令时沿用上游日期提示，只有用户明确点击才减一小时，支持撤销；会跨日的情况需要用户同时核对日期和时间。未知出生时辰暂按本日子时，仅为占位盘。
